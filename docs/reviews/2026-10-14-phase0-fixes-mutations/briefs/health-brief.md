## Controller rulings
1. `alertGate` (one small type, used by every rule): `fire(key, title, body)` sends at most once per 6 h per key while active; `clear(key, title)` sends exactly one "recovered" message if the key had fired and is now cleared, then resets. Condition rules (`disconnected` too long, `no_events`, `phone_quiet`, `disk`) clear when the condition stops holding (checked in `check()` and on `Seen`/`SetState`). Immediate state alerts (`logged_out`, `temp_banned`, `stream_replaced`, `client_outdated`) clear when the state becomes `connected`. Event alerts (`write_failed`, `panic:<where>`) are gated only (no recovered). `backup` clears on the next successful `BackupResult`.
2. Disconnected rule: the monitor records when the state left `connected` (for state `disconnected` only — the others alert immediately); `check()` fires when `now - since > DisconnectedAfter` (body says how long). Before any `connected` has been seen (startup), measure from monitor creation time.
3. Phone-quiet: `now - PhoneLastActive > PhoneQuietAfter` (from monitor creation if never seen); body: "open WhatsApp on your phone to avoid the 14-day unlink".
4. `client_outdated` body names `versionInUse()`; `temp_banned` body includes the detail (expiry) and says capture is paused.
5. M2: `Run(ctx)` owns one sender goroutine reading a bounded channel (capacity 16); `alert` enqueues non-blocking; when full, drop and log at Error (the gate already limits volume). Notify uses Run's ctx so SIGTERM cancels it. Alerts raised before `Run` starts wait in the channel. `Run` returns only after the sender goroutine exits (join it). `Monitor` gains a logger only if needed (prefer an optional field/arg with least churn; update `serve` wiring).
6. Times: all rules use the injected `Clock`; tests never real-sleep (the minute ticker in `Run` — tests call `check()` via an exported-for-test or in-package test; health tests may be in package `health` if they already are; keep consistent).
