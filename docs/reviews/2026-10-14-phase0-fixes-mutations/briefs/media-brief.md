## Controller rulings
1. Panic boundary: `NewQueue` gains a way to report panics (e.g. an `onPanic func(where string)` argument or a small interface with `Panic(string)` — `health.Monitor` already has `Panic`); `serve` wires `mon.Panic`. The worker remembers its current row; on panic the row is set `failed` with reason `panic` (through the store, ctx-aware), `Panic("media")` is called once, and the worker continues with the next row. Recovery stays in `guard.Run` (one panic guard).
2. MediaRef: replace the empty struct use with fields from the row: chat JID, sender JID, message ID, from_me. Add a `from_me` column to `media` (edit `0001_raw.sql` — M11 migrations deferred, no deployed DB; note it in PROGRESS) set at enqueue from `Result.FromMe`. `wa.RequestMediaRetry(ctx, ref, raw)` parses the JIDs, builds `types.MessageInfo{MessageSource{Chat, Sender, IsFromMe, IsGroup}, ID}` and extracts the media key from the raw proto via the existing `mediaMessage` helper (unwrap wrappers first — reuse whatever the download path uses). Errors wrapped; a row without a media key → `failed` reason "no media key". Unit-test the info/key construction inside `wa` with a pure helper (no client, no network); test the queue with a fake Downloader that records the ref.
3. Rate limit: limiter driven by `q.clock.Now()` (`AllowN`/`ReserveN` with explicit time). Expired rows not yet requested are revisited by a periodic pass in the worker loop (each wake/tick): request while the limiter allows, mark `retry_requested`, leave the rest `expired` for the next pass. A restart revisits `expired` rows too. Keep `retry_requested` → `failed` after 24 h (existing `ResetMediaOnStart`), and also apply that expiry in the periodic pass using the clock.
4. M4 backoff: per round, `retry.Do(Policy{Max: 5, Base: 1 * time.Second, Sleep: injectable})` (1+2+4+8 s). After a round fails with a transient (non-expired) error: if total attempts < 20, set state `pending` with a not-before time of now + 15 minutes (add a `next_attempt_at` column; `ClaimMedia` claims only rows with `next_attempt_at <= now` — pass `now` from the clock); else `failed` with the reason. The queue's sleep is injectable so tests never real-sleep. Cost if wrong: a permanently bad file is retried 4 rounds over ~45 min before `failed`.
5. One retry helper (`internal/retry`), one panic guard (`internal/guard`). Store writes in the queue currently ignore errors (`_ = q.store.UpdateMedia`) — log them at Error with the row identity (don't build a second retry-forever here; the row is re-claimable after restart). No new goroutines beyond the existing workers; every goroutine stops on ctx cancel; tests cancel and wait for `Run` to return (no `time.Sleep` in new tests; fix the existing 50 ms sleep only if your test needs it — do not weaken it).
