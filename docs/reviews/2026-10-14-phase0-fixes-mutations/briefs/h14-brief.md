## Controller rulings
1. Recorded file format (one JSON file per event, `<seq>-<kind>.json`): `{"kind": ..., "info": <JSON>, "proto": <base64 or omitted>}`. For message/undecryptable: `info` = `json.Marshal(types.MessageInfo)` (all fields: chat, sender, alt JIDs, from_me, group, ID, push name, timestamp, …) and `proto` = the raw message (message) or none. History sync: `proto` = `proto.Marshal(evt.Data)`. Group info / joined group: `info` = JSON of the whatsmeow struct (verify it round-trips — if a field doesn't, use a small local struct; JIDs marshal as text). Archive/mute/pin: `info` = `{jid, timestamp, from_full_sync}`, `proto` = the `Action` proto. Media retry: `info` = the struct fields. `Load` rebuilds the exact Go event types `Handle` routes. Round-trip test per kind compares with `proto.Equal` / `reflect.DeepEqual` (normalise time locations to UTC). Recorder write errors are logged, never block the handler; recording must not change what `next` receives.
2. Scrub (rebuild): decode each recorded file; replace identifiers in every JSON string value and, after base64-decoding `proto`, in every protobuf string field recursively (walk with `protoreflect`, including repeated and map fields and nested messages), then re-encode. Identifier forms: `<digits>@s.whatsapp.net`, `<digits>:<device>@s.whatsapp.net`, `<digits>@lid`, `<digits>:<device>@lid`, `<digits>.<agent>:<device>@…` if present, and bare phone-number strings in fields whose name contains `jid`, `participant`, `phone` or `number` (digits ≥ 8). Mapping is stable per run AND across runs: fake = deterministic hash of the user part, keeping the server and device suffix (so `X:12@s.whatsapp.net` → `F:12@s.whatsapp.net`). Group JIDs (`@g.us`) keep as-is? NO — they can identify groups: scrub them too, same stable scheme. Also clear every `bytes` protobuf field whose field name ends in `key` (media keys, key data) — fixtures never need real keys (closes the H8 M6 recorder concern). Text content is kept.
3. CLI: `archiver scrub <in> <out>` (calls `Scrub`) and `archiver replay <events-dir> --data <dir>` (Load → fresh pipeline on `<data>/archive.db` with the real store, filter from config, a no-op media queue and a no-op health sink → prints `replayed <n> events` and the `DumpRaw` path or prints the dump to stdout with `--dump`). Least code; reuse `Load`/`Replay`/`DumpRaw`. Replay never connects to WhatsApp and never imports the wa client path (history parsing in replay: use `wa.NewHistoryParser` with a fixed own JID from a `--own <jid>` flag, default a placeholder — or skip own-message attribution with a clear note; pick least code and document).
4. `DumpRaw`: for each raw table in a fixed order, `SELECT` all columns except `received_at` (and `first_seen` for id_mappings if it is a receive time — check), `ORDER BY` every column, format each row as an `INSERT INTO <table>(cols) VALUES(...);` line with blobs as `X'hex'`. Deterministic.
