## B2 (verbatim evidence from docs/reviews/2026-10-14-phase0-review.md)
The reconnect loop has no backoff and ignores account states. (a) After `ClientOutdated` it calls `Disconnect`, re-decides the version and re-dials immediately; with `version_override` and the check off it re-uses the same rejected version, so it hammers the real account's handshake in a tight loop. The plan's 30-minute wait exists only if the version refresh itself errors. (b) whatsmeow marks 405, `TemporaryBan`, `LoggedOut` and `StreamReplaced` as expected disconnects so it will not reconnect on its own; our outer loop re-dials every 5 s anyway. After `TemporaryBan` and `StreamReplaced` that is a live re-dial every 5 s, contradicting RISK-1 "alert and pause capture". After `LoggedOut` whatsmeow has deleted the device, so each attempt fails instantly with `ErrDeviceDeleted`, logging every 5 s forever. (c) After the first successful 5 s tick the code blocks in `<-ctx.Done()`, so a later `ClientOutdated` is never read: SC-9's "reconnects without a new build" cannot happen while running. (d) `go printQR` is spawned on every loop pass. (`internal/wa/wa.go:115-143`; whatsmeow `connectionevents.go:107-111,126-141`, `:41-51`.)
Fix (review): extract the reconnect policy into a small pure state machine (event in, action out) and unit-test it with an injected sleep. Red tests (names fixed): `TestClientOutdatedSameVersionWaits30Minutes`, `TestOutdatedAfterConnectedTriggersRefresh`, `TestTemporaryBanPausesCapture`, `TestLoggedOutStopsTheReconnectLoop`, `TestStreamReplacedBacksOff`.
Plan text (binding, Task 4): "`Run` … connects; if `pairing` and not yet paired, prints QR codes to the terminal; registers `h` as the synchronous event handler (no channel in between, so a slow write slows whatsmeow instead of piling up events); reconnects; after a `ClientOutdated` event, re-runs `decideVersion` and reconnects with a newer version if one exists, otherwise waits 30 minutes and tries again; returns only on context cancel." RF4: "the process stays up reporting `logged_out` or `temp_banned` instead of crash-looping". RF6: "a fresh version check before each reconnect, no crash loop". Charter RISK-1: on a temporary ban "alert the user and pause capture".

## Controller rulings (follow them; record deviations)
1. Pure policy in its own file, e.g. `internal/wa/reconnect.go`: a small type that takes an input (one of: start, connect-failed(err), connected, client-outdated + whether the refreshed version differs, temporary-ban(expire), logged-out, stream-replaced, with the current time) and returns an action: `{connect, disconnect, refreshVersion, wait time.Duration, stop}` (shape is yours, keep it minimal). No goroutines, no I/O, no sleeping inside it.
2. Behaviour table:
   - start → connect.
   - connect failed (error from ConnectContext, not ctx cancel) → wait then connect; wait doubles from 5 s to a 5-minute cap; reset on connected.
   - connected → nothing (keep listening; whatsmeow's own auto-reconnect handles ordinary `Disconnected`).
   - client outdated → disconnect + refresh version (re-run `decideVersion`); if the version in use changed → connect now; if unchanged (or refresh failed) → wait 30 minutes, then refresh again and connect. This applies at any time, including long after connected.
   - temporary ban → disconnect, pause for `Expire` plus 1 minute; if `Expire == 0` pause 24 hours; then connect. Cost if wrong: one attempt per day during an indefinite ban.
   - logged out → stop reconnecting for good; `Run` keeps blocking until ctx is cancelled and then returns nil (the process stays up reporting logged_out; health already alerts via the pipeline's `SetState`).
   - stream replaced → disconnect, wait 5 minutes, doubling per consecutive replace up to a 1-hour cap; the doubling resets to 5 minutes if the previous replace was more than 6 hours earlier; then connect.
   - Disconnected events → nothing.
3. `Run` wiring: the whatsmeow event handler calls `h(evt)` synchronously (keep that), then for the control events above does a non-blocking send onto a buffered channel (size ≥ 8) read by the `Run` loop; the loop feeds the policy and executes actions with a context-aware injected sleep. `printQR` is started at most once. `Run` returns only on ctx cancel (nil) — keep the existing "already paired"/"not paired" checks unchanged (H18 is a separate later finding; don't touch it).
4. Testability: the socket boundary becomes a tiny interface (`ConnectContext(ctx) error`, `Disconnect()`, maybe `IsConnected()`) satisfied by `*whatsmeow.Client`; the version refresh is a func field. Tests in package `wa` (internal, like existing `wa_test.go`) may drive `Run`'s loop with a fake socket, a fake sleep (records durations, returns immediately or blocks on a channel) and injected events. Test both the pure policy and at least one loop-level test for `TestOutdatedAfterConnectedTriggersRefresh` (proving the loop still reads ClientOutdated after Connected — the old bug (c)).
5. Never real-sleep in tests; never touch the network; never construct a real whatsmeow connection. No goroutine leaks: every goroutine stops on ctx cancel; tests cancel and wait.
6. Least code; remove the old loop entirely (no dead code). Errors wrapped with context.
