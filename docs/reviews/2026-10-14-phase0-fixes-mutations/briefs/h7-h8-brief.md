## H7 (verbatim)
Group, archive, mute and pin events keep almost nothing and are not idempotent. `Value` is only `Notify`/`Reason`/the constant "archive"/"mute"/"pin": the new group name, topic, joins, leaves, promotions, `Sender`, and whether the chat is now archived/muted/pinned are all dropped; the WhatsApp timestamp is not stored; no raw payload is kept; `KindParticipants` is never produced. The `EventID` hashes `fmt.Sprintf("%v", evt)`, which prints pointer addresses, so the same event gets a different ID each time and redelivery duplicates. Mutation `y3` (chat events not routed) survives. Fix: marshal the event payload (JSON, or the `Action` proto for app-state events) into `Value`/`RawProto`; take the timestamp from the event; derive the ID from stable fields. Red tests: `TestChatEventsStored` (Table 1 name; through `Pipeline.Handle` into the real store), `TestSameGroupInfoTwiceIsOneRow`, `TestArchiveOnAndOffAreDistinct`.

## Controller rulings
1. Non-edit, non-revoke protocol messages (EPHEMERAL_SETTING, HISTORY_SYNC_NOTIFICATION, APP_STATE_SYNC_KEY_SHARE, etc.): not a revoke and not a message. Store them as a message event of kind `protocol` with `Value` = the type name, target = key ID if any (keeps raw data, CON-2 insert-only, no "deleted" claims). If adding a Kind constant is needed, add `KindProtocol`. Filter (`scope.go`) treats it like other message events. Cost if wrong: extra rows that analysis can ignore.
2. Edit shapes: (a) `ProtocolMessage{Type: MESSAGE_EDIT, Key, EditedMessage}` and (b) the top-level `EditedMessage` wrapper (`evt.IsEdit` after `UnwrapRaw`, where the inner message is the protocol message or the new content — read UnwrapRaw and the proto to decide). Both → `KindEdit`, `TargetID` = original message ID, `NewText` = new text. Tests construct both shapes with real proto types.
3. Poll votes: cover `PollUpdateMessage` (current) and any newer poll-vote shape present in the pinned waE2E proto (look for poll creation V2/V3/V5 and vote-related fields; if only one vote shape exists, the "newer version" case is a vote on a `PollCreationMessageV3`/V5 key — document what you found). Vote content is encrypted; store target + raw proto.
4. Chat events: `Value` = compact JSON of the stable, meaningful fields per type (GroupInfo: Name/Topic/Announce/Locked/Ephemeral/Join/Leave/Promote/Demote/Notify/Sender as JIDs strings; JoinedGroup: Reason/Type/group name; Archive/Mute/Pin: the `Action` state, e.g. archived true/false, mute end timestamp, pinned true/false, plus `FromFullSync`). `RawProto` = `proto.Marshal(Action)` for app-state events; for group events, the JSON is the payload (no proto available) — RawProto may stay empty there. Timestamp from the event (`Timestamp` field). `SenderJID` from the event when present. `EventID` = stableID over chat, kind and the canonical JSON + timestamp (deterministic; same payload twice → same ID; on vs off → different IDs). GroupInfo with Join/Leave/Promote/Demote → `KindParticipants` (one row per GroupInfo event is fine; if it carries both name changes and participant changes, choose one documented rule).
5. Pure functions only in the normaliser; JSON via `encoding/json` on a small local struct (not marshalling whatsmeow structs wholesale, which may contain unexported/pointer-heavy fields).
