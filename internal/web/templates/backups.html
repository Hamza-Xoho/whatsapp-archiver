How to restore

There is no restore button: restoring replaces the archive, so you run it yourself. session.db is never backed up, copied or restored: after a restore on a new server you pair again, with the snapshot's archive.db placed in the new data folder first.

To restore, first check the newest snapshot in a scratch folder. This does not touch the live archive:

sudo -u whatsapp-archiver sh -c 'mkdir -p -m 700 /var/tmp/snapshot-check && cp "$(ls -1d {{.Dest}}/*/ | tail -n 1)archive.db" /var/tmp/snapshot-check/'
sudo -u whatsapp-archiver /opt/whatsapp-archiver/archiver status --data /var/tmp/snapshot-check
sudo rm -r /var/tmp/snapshot-check

Then, with the service stopped, put that archive.db in a fresh data folder ({{.DataDir}}), check it with PRAGMA integrity_check, start the service and pair again on the Pairing page. The full commands are in the README, section 13, Restore a backup.
